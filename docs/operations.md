# История и исправление операций

Все новые начисления записываются в историю: тип, длительность, время, причина,
источник, инициатор, внешний ID и состояние игрока до/после. Для старых дат история
задним числом не придумывается — первая операция сохранит исходное состояние.

## Команды

Нужны права `joupen.admin`.

```text
/joupen prolong Player 30d Покупка проходки
/joupen gift Player 3d Приз за турнир
/joupen compensate Player 12h Простой сервера
/joupen adjust Player -3d Исправление срока
/joupen adjust Player +12h Дополнительное время
/joupen history Player
/joupen history Player 2
/joupen undo Player
/joupen undo Player last Ошибочная выдача
/joupen undo Player 42 Возврат платежа
```

`history` показывает по 10 записей, сначала новые. У каждой есть ID для `undo`.
`undo` без ID берёт последнюю ещё не отменённую операцию; системные записи первого
входа и миграции, а также сами отмены пропускаются.

`undo` не пересчитывает прошлое: для `+30d` он добавляет запись `-30d` и вычитает
30 дней из текущего срока. Последующие начисления не откатываются. Отменить одну
операцию дважды нельзя. Если требуется другое итоговое время, используется `adjust`.
Положительная корректировка просроченной проходки считается от текущего момента,
отрицательная — от сохранённого срока. При `undo` обратное изменение всегда
применяется к сохранённому сроку, даже если он уже в прошлом.

Существующий формат времени пока сохранён: `mo` — 30 дней, `d` — день, `h` — час,
`m` — минута. Знак разрешён для `adjust`; обычная выдача принимает только
положительную длительность.

## Автоматические запросы

К командам выдачи, корректировки и отмены можно добавить источник и внешний ID:

```text
/joupen prolong Player 30d Оплата --source=shop --external-id=payment-123
/joupen undo Player 42 Возврат --source=shop --external-id=refund-123
```

Пара `source` + `external-id` уникальна. Повтор возвращает ID первой операции,
не меняет состояние и не повторяет уведомления. Другой игрок, тип операции или
длительность под той же парой отклоняются. Отмена исходной выдачи не освобождает
её внешний ID для повторного начисления. Без внешнего ID каждый вызов считается
новой операцией. Для `all` к ID добавляется ник: повтор защищён отдельно для каждого
игрока. Источник приводится к нижнему регистру, регистр внешнего ID сохраняется.

В `gifts.txt` и `scheduled-gifts.txt` старые строки автоматически получают ID
последним столбцом. Он сохраняется до начисления; оставшаяся после сбоя строка
безопасна для повторной обработки. При новой выдаче нужна новая строка без старого
ID либо с новым ID. Удаление этих файлов из механики плагина остаётся отдельной задачей.

## Структура

- `PlayerOperationService` применяет операции и их обратные изменения.
- `PlayerRepository.applyOperation` сохраняет изменение вместе с историей.
- В SQL используются `player_operations` и транзакционная блокировка `operation_lock`.
- В файловом режиме `operations` хранятся внутри записи игрока в `player.json`;
  файл заменяется атомарно. Старый массив игроков читается без ручной конвертации.
- `PlayerService` сохраняет прежние методы продления и отправляет существующие
  события только после успешного сохранения.

Approval и временные окна записываются методами `approval` и `temporaryAccess`
в `PlayerOperationService`. Их `undo` восстанавливает прежний флаг или окно,
не меняя обычную проходку. Сервис доступен через
`JoupenPlugin.getInstance().getPlayerService().getOperations()`.
Новые интерфейсы управления окнами, pending/paid и уведомлениями сюда не входят.

## Обновление сервера

SQL-схема обновляется автоматически до запуска репозитория. Существующие игроки
получают approval, новые — нет. Устаревшая настройка `plugin.migrate` удаляется из
конфига, `player.json` в SQL не переносится. Перед обновлением стоит сохранить копию
БД или `player.json`. В файловом режиме нельзя возвращать старый JAR с записью
в тот же файл: старая версия не знает о поле `operations` и может потерять историю.

Новые тексты настраиваются в секции `messages` конфигурации. В старом конфиге
отсутствующие ключи используют значения по умолчанию.
